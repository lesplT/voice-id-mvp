# Voice ID MVP

CPU-friendly MVP: три независимых сервиса обработки аудио и единый интерфейс на русском.

## Запуск всего проекта в Docker

```powershell
docker compose -f compose.docker.yml up -d --build --wait --wait-timeout 1800
```

Docker-интерфейс: **http://127.0.0.1:18000/**. Готовые модели подготавливаются автоматически,
журнал и голосовая база сохраняются на диске. Код опубликован отдельно от личных данных.
Инструкции запуска, переноса существующих данных и резервного копирования — [DOCKER.md](DOCKER.md).
Команды ниже описывают прежний запуск непосредственно в Windows на порту 8000.

## Единый интерфейс

Откройте **http://127.0.0.1:8000/** — это основная страница, вместо трёх отдельных `/docs`.

- **Диалог:** выберите запись разговора и нажмите «Разобрать диалог». Результат показан карточками с именем, временем и текстом. Нажмите время реплики, чтобы прослушать этот момент.
- **Голоса:** регистрация нового человека, список сохранённых голосов и проверка «Чей это голос?». Уже зарегистрированные `platon` и `prokhor` отображаются как Платон и Прохор. Запись с тем же именем дополняет образцы, а не удаляет их.
- **Расшифровка:** текст записи без разделения по людям. Можно скопировать текст, сохранить TXT или нажать отдельную кнопку «Сохранить JSON».
- **Словарь:** создайте слово, при необходимости укажите категорию и варианты ошибок — каждый с новой строки. Затем прикрепите аудиопримеры с правильной текстовой подписью. Примеры можно прослушать в карточке слова.
- **Журнал:** все новые диалоги и расшифровки сохраняются вместе с исходным аудио, датой и результатом. Открывайте, слушайте и ищите прошлые записи, сохраняйте аудио/TXT/JSON. Хранятся до ручного удаления.

Установить дополнительные программы для самого интерфейса не нужно. Для запуска из PowerShell:

```powershell
cd C:\Users\PC\voice-id-mvp
.\scripts\start_all.ps1
```

Если сервисы уже работают, используйте `.\scripts\stop_all.ps1`, затем снова `start_all.ps1`.
Скрипт останавливает только проверенные процессы этого проекта и их дочерние интерпретаторы.
Не освобождайте порты остановкой неизвестных процессов.

Обработка не блокирует страницу: сервер ставит запись в очередь (не более четырёх незавершённых задач),
страница показывает состояние и прошедшее время. Проценты готовности не выдумываются.
Состояния задач хранятся в памяти около часа (не более 20 задач), но диалоги и расшифровки
дополнительно сохраняются в постоянный журнал. После обновления страницы или перезапуска
откройте вкладку «Журнал». Словарь и голоса также сохраняются.

### Журнал разговоров — до ручного удаления

Исходный аудиофайл сохраняется **до начала обработки**, результат — по её завершении.
При ошибке или заполненной очереди файл остаётся доступен в журнале. При перезапуске
незавершённая задача отмечается «Обработка прервана»; скачайте аудио и загрузите его снова.
Нет автоматического удаления по возрасту или количества записей. Для просмотра используются
поиск по имени файла/тексту и страницы по 30 записей; счётчик показывает размер аудио.

Регистрация клиента не требуется: UNKNOWN не отключает распознавание текста.
Метка «Неопределённый участник» не означает гарантированно «покупатель»: так может
обозначаться и короткая неузнанная реплика сотрудника. Ошибочное совпадение голоса возможно;
журнал не является доказательством авторства реплики без прослушивания.
Выделение нескольких неизвестных людей и одновременной речи не гарантируется.

Журнал расположен в `data/journal` (`journal.sqlite3` и `audio/*.bin` — исходные аудиобайты
без перекодирования), путь задаётся `JOURNAL_PATH`. Для резервной копии остановите сервисы
и скопируйте **всю** эту папку. Она содержит личные сведения и исключена из исходного ZIP.
Записи, сделанные до добавления журнала, автоматически не появятся: загрузите файлы снова.
Автоматическое сохранение действует при загрузке через страницу/`POST /api/jobs` на 8000;
прямые старые маршруты на 8003 не создают запись журнала.

Кнопка «Удалить запись» после подтверждения **окончательно удаляет** эту запись, её
исходное аудио и сохранённый результат. Это не архив и не корзина; отдельно сделанные копии
не затрагиваются. Удаление во время обработки запрещено. Уже скачанный результат и временное
состояние задачи в памяти до перезапуска/истечения срока не являются частью постоянного журнала.
Данные не зашифрованы и доступны пользователям с доступом к папке ноутбука. Сервисы остаются
локальными, без пароля; не публикуйте их наружу и ограничьте доступ к ноутбуку.

API журнала: `GET /api/journal?q=...&limit=30&offset=0`, `GET /api/journal/{id}`,
`GET /api/journal/{id}/audio` (параметр `download=true` для скачивания), `DELETE /api/journal/{id}`.

### Как работает словарь

Пример: правильное слово `чиабатта`, вариант ошибки `чааббат`.
При включённой галочке «Использовать словарь» исправляются **только явно заданные варианты**,
по границам слов или фраз. Похожие слова не угадываются. Номера телефонов и имена говорящих
не меняются. Исходный текст доступен через «Показать исходный текст до словаря»;
JSON содержит `original_text` и `dictionary_corrections` — список фактических изменений.

Аудиопримеры — сохраняемые размеченные записи, **не автоматическое обучение модели**.
Простое добавление аудиофайла не меняет веса GigaAM и не гарантирует улучшение узнавания слова.
Если у слова нет вариантов ошибки, оно и его аудиопримеры сохраняются, но текст не подменяется.

Пример: 0,35–30 секунд, не более 15 МБ, до 20 примеров на слово. Должна присутствовать речь.
Входные аудиофайлы обычных задач — до 100 МБ. Словарь находится в `data/dictionary`
(SQLite и нормализованные WAV под случайными идентификаторами), путь можно задать `DICTIONARY_PATH`.
«В архив» скрывает слово и выключает исправления, но сохраняет записи на диске.
Восстановление архива через интерфейс пока не реализовано.

Старые маршруты на 8001–8003 остаются доступны. Для прямого API можно включить словарь запросом
`POST /transcribe?use_dictionary=true` или `POST /dialogue?use_dictionary=true`.
Без параметра старые endpoints по-прежнему возвращают исходный текст.
Все сервисы слушают только localhost; пароль и публикация в интернет не добавлялись.

## Архитектура

| Сервис | Порт | Основные endpoints |
|---|---:|---|
| Интерфейс | 8000 | Главная страница, `/api/jobs`, `/api/speakers`, `/api/dictionary`, `/api/journal` |
| Enrollment | 8001 | `POST /speakers/{speaker_id}/enroll`, `GET /speakers`, `DELETE /speakers/{speaker_id}` |
| Identification | 8002 | `POST /identify` |
| Transcription | 8003 | `POST /transcribe`, `POST /dialogue` |
| Qdrant | 6333 | Cosine-хранилище embeddings и центроидов |

Поток данных:

1. FFmpeg приводит вход к WAV PCM s16le, mono, 16 kHz.
2. Основной Voice ID движок — готовая SpeechBrain ECAPA-TDNN (192 числа на голосовой отпечаток). `SPEAKER_ENGINE=vosk` сохраняет прежний вариант Vosk (128 чисел); для него нужна отдельная коллекция и прежние пороги.
3. Каждый embedding L2-нормализуется. Центроид строится по нормализованным embeddings и ещё раз L2-нормализуется.
4. Каждый enrollment сохраняет отдельные reference vectors и centroid в Qdrant.
5. Identification запрашивает top-K точек, группирует их по `speaker_id` и усредняет три лучших cosine score референсов каждого человека. Центроиды сохраняются для анализа, но не дублируют референсы в поиске. При малом числе референсов используются все доступные. Глобальный top-K может скрыть второго кандидата, если у первого очень много референсов; увеличивайте top-K по мере роста базы.
6. Энергетический VAD выделяет речь, затем ECAPA проверяет смену голоса окнами 0.8 секунды с шагом 0.2 секунды. Новая граница требует двух последовательных уверенных окон. Каждый полученный фрагмент отдельно проверяется по обычному порогу Voice ID и расшифровывается; текст не используется для выбора человека.

## Требования и подготовка

- Windows 10/11 x64.
- Python 3.11. Python 3.14 для текущего Vosk/ML-стека не использовать.
- FFmpeg в PATH либо bundled binary из `imageio-ffmpeg` (установлен базовым lock-файлом).
- 4 CPU cores, 8 ГБ RAM минимум; 16 ГБ предпочтительно.
- Около 3 ГБ свободного места для базового профиля. Для GigaAM нужен дополнительный запас под PyTorch и веса.
- Docker Desktop желателен для Qdrant, но необязателен.

## Конфигурация

Скопируйте `.env.example` в `.env` и измените значения. Проверенный профиль `.env` настроен на `ASR_ENGINE=gigaam` с автоматическим Vosk fallback.

Ключевые параметры:

| Параметр | Стартовое значение | Назначение |
|---|---:|---|
| `VOICE_ID_THRESHOLD` | 0.45 | Минимальное сходство голосов для ECAPA; это не вероятность |
| `VOICE_ID_MARGIN` | 0.12 | Минимальный отрыв первого кандидата от второго |
| `VOICE_ID_MIN_SECONDS` | 0.35 | Технический минимум входной записи, не гарантия узнавания |
| `VOICE_ID_TOP_K` | 20 | Число reference/centroid hits из Qdrant |
| `VAD_MIN_SEGMENT_SECONDS` | 0.35 | Минимальный речевой сегмент |
| `VAD_MAX_SEGMENT_SECONDS` | 20 | Максимальная длина сегмента |
| `VAD_PADDING_MS` | 240 | Контекст до и после активности |

Эти threshold и margin — только стартовые значения. Их необходимо калибровать на реальных записях Платона: разные микрофоны, расстояния, помещения, шум и эмоциональная речь заметно меняют распределение score.

### Причины UNKNOWN

- `too_short` — реплика короче `VOICE_ID_MIN_SECONDS`; она не приписывается известному человеку.
- `no_speech` — VAD не нашёл речь.
- `no_embedding` — Vosk не вернул embedding либо в базе нет кандидатов.
- `below_threshold` — лучший score ниже threshold.
- `ambiguous` — два лучших speaker слишком близки, отрыв меньше margin.

## Qdrant

`scripts\start_all.ps1` сначала проверяет Docker Engine. Если он доступен, выполняется `docker compose up -d qdrant`.

Если Docker Engine недоступен, скрипт задаёт `QDRANT_URL=local` только в окружении запуска и включает `qdrant-client local mode` в `data\qdrant_local`. Доступ из трёх процессов сериализуется через `filelock`; это рабочий fallback для MVP, но серверный Qdrant лучше при параллельной нагрузке.

## ASR: GigaAM-v3 и Vosk fallback

Основной quality backend в коде — `GigaAM-v3 e2e_rnnt`. Модель загружается лениво только при первом запросе, явно на CPU и без fp16 encoder. Установка отделена от базового MVP, потому что она добавляет PyTorch и крупные веса:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-gigaam.txt
(Get-Content .env) -replace '^ASR_ENGINE=.*$', 'ASR_ENGINE=gigaam' | Set-Content .env
.\scripts\stop_all.ps1
.\scripts\start_all.ps1
```

Если импорт или загрузка GigaAM падает и `ASR_FALLBACK_TO_VOSK=true`, запрос автоматически обрабатывается Vosk, а ответ содержит `fallback_reason`. GigaAM проверен на этом CPU; для более лёгкого режима можно выбрать `ASR_ENGINE=vosk` и перезапустить сервисы.

## Ограничения

- Это identification по зарегистрированным голосам с простым акустическим поиском смены человека, а не универсальная diarization-модель.
- Энергетический VAD не разделяет двух людей, говорящих одновременно, и хуже работает при постоянном громком шуме.
- Реплики короче 0.35 секунды возвращают `UNKNOWN/too_short`; остальные могут остаться UNKNOWN из-за слабого сходства или неоднозначности.
- Один референс недостаточен. Для каждого человека желательно 3–5 записей по 8–20 секунд с разными микрофонами и акустикой, но без музыки и чужой речи.
- Синтетический smoke test не говорит ничего o false accept/false reject на людях.
- Для калибровки нужны позитивные и негативные пары Платона, после чего threshold/margin выбираются по измеренному компромису ошибок.
- Сервисы слушают только `127.0.0.1`; наружу ноутбука они не опубликованы.

## Troubleshooting

**`FFmpeg failed to start`**  
Сначала проверьте `ffmpeg -version`. Если системного FFmpeg нет, код автоматически пробует bundled binary из `imageio-ffmpeg`; его путь можно увидеть командой `.\.venv\Scripts\python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"`. При необходимости задайте абсолютный путь в `FFMPEG_BIN`.

**Docker CLI есть, но Engine недоступен**  
Запустите Docker Desktop и дождитесь состояния Engine running. До этого `start_all.ps1` автоматически использует local mode.

**`Speaker model is missing` / `Vosk ASR model is missing`**  
Повторно выполните `.\scripts\download_models.ps1`.

**Порт занят**  
Проверьте `Get-NetTCPConnection -LocalPort 8001,8002,8003,6333 -State Listen`. Не убивайте неизвестный процесс; измените порт запуска либо остановите только известный сервис.

**GigaAM очень медленный или не хватает памяти**  
Верните `ASR_ENGINE=vosk`. Модель Vosk уже установлена и не требует GPU.
