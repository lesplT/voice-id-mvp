# Сравнение моделей Voice ID

На контрольном прогоне 16 ноября 2026 GigaAM v3 лучше распознал русский текст,
а Nemotron 3 Diarization лучше разделил говорящих. Результат поддерживает
связку **GigaAM для текста + NeMo для разделения говорящих** для дальнейшей
проверки на записях пекарни.

## Результаты контрольного прогона

**Распознавание:** все три модели обработали те же 100 клипов русских звонков
(3 мин 36 с, 622 слова в ручной разметке).

| Модель | WER ↓ | Заменено | Пропущено | Добавлено | Слов на выходе |
|---|---:|---:|---:|---:|---:|
| GigaAM v3 RNNT | **18,8%** | 80 | 21 | 16 | 617 |
| Nemotron 3.5 ASR Q8 | 43,1% | 152 | 103 | 13 | 532 |
| Vosk small ru 0.22 | 48,1% | 204 | 78 | 17 | 561 |

**Диаризация:** обе модели обработали по два двухминутных фрагмента английских
встреч ICSI. Одновременная речь учитывалась. В ошибках ниже время, когда
говорили двое, может учитываться для обоих.

| Модель | DER суммарно ↓ | Bdb001 | Bed004 | Пропуск, с | Лишняя речь, с | Перепутанные голоса, с |
|---|---:|---:|---:|---:|---:|---:|
| Текущий метод VAD + ECAPA | 49,1% | 36,8% | 65,0% | 51,21 | 21,09 | 45,68 |
| Nemotron 3 Diarization Q8 | **28,5%** | **26,0%** | **31,8%** | 33,18 | 26,88 | 8,48 |

**Voice ID по имени:** текущий метод правильно подписал **73,0%** времени
одиночной речи зарегистрированных участников (94,55 с из 129,45 с).
Оставил `UNKNOWN` на 24,98 с, перепутал имя на 5,17 с и пропустил 4,75 с.
Из 40,38 с одиночной речи незарегистрированных участников метод ошибочно
присвоил имя на 8,23 с. Сам Nemotron возвращает номера, поэтому точность по
именам напрямую с ним не сравнивается.

Машинные отчёты выполненного прогона: `data/bench/open-stt-results` и
`data/bench/icsi-results`. Эти результаты относятся к выборкам, а не ко всему
Open STT или ICSI. Весь прогон выполнен локально на процессоре ноутбука.

## Расширенный прогон

Расширенная выборка включает первые 100 фрагментов Open STT и два фрагмента ICSI.
С теми же моделями и настройками дополнительно обработаны 200 фрагментов звонков
и по две минуты из шести встреч ICSI. Все модели обработали все записи своей группы.

| Звонки Open STT | Все 300 фрагментов, WER ↓ | 54 фрагмента короче секунды, WER ↓ |
|---|---:|---:|
| GigaAM v3 RNNT | **20,5%** | **26,4%** |
| Nemotron 3.5 ASR Q8 | 42,4% | 71,3% |
| Vosk small ru 0.22 | 50,2% | 62,0% |

Это 2,32% раздела `asr_calls_2_val`, всего 10 мин 24 с аудио и 1799 слов по
разметке. В подгруппе короче секунды — 129 слов по разметке.

| Говорящие, ICSI | DER ↓ |
|---|---:|
| Текущий метод VAD + ECAPA | 45,2% |
| Nemotron 3 Diarization Q8 | **24,1%** |

NeMo показал меньший DER на каждом из восьми фрагментов. Взяты 16 минут
из восьми встреч (10,7% встреч корпуса). Текущий Voice ID подписал правильным
именем 73,1% времени одиночной речи зарегистрированных участников. Имена
проверялись с образцами из более ранней части той же встречи.

Результаты доступны в `data/bench/open-stt-300-results` и
`data/bench/icsi-8-results`. Для повтора используйте команды контрольного
прогона ниже с `--count 300` и списком встреч
`Bdb001 Bed004 Bmr007 Bmr010 Bed012 Bro016 Bro004 Bro024`.

## Отдельное окно сравнения

В отдельном приложении выберите папку с аудио, папку для отчётов и нужные модели.
Приложение работает на ноутбуке без запуска веб-сервисов и обходит вложенные
папки. По каждой записи сохраняются текст, количество слов, интервалы говорящих,
число реплик и длительность речи. Если одна модель не обработала файл, её ошибка
появится в отчёте, а другие модели продолжат работу.

```powershell
cd C:\Users\PC\voice-id-mvp
.\scripts\start_benchmark.ps1
```

На чистой установке сначала выполните основную настройку из README и установите
[GigaAM v3](requirements-gigaam.txt), если она ещё не установлена. Затем установите
NVIDIA NeMo и обе модели (около 850 МБ весов и примерно 1 ГБ свободного места на
установку; большие папки аудио требуют дополнительного места для временных WAV):

```powershell
.\.venv\Scripts\python.exe -m voice_id_mvp.benchmark.setup_nemo
```

В результатах `comparison.csv` — таблица для Excel, `summary.json` — сводка,
`recordings/*.json` — исходный вывод каждой модели по отдельной записи. Если
есть ручная расшифровка, положите её рядом с записью: например, для `call.wav`
это `call.txt` в UTF-8. Для диаризации положите рядом `call.rttm` — стандартный
текстовый файл с интервалами речи каждого участника. Без эталонов приложение
выводит подсчёты, но оставляет показатели точности пустыми.

## Что измеряется

- **WER** — число замен, пропусков и добавлений слов, делённое на число слов
  в ручной расшифровке. Ниже — лучше. Для всех моделей одинаково игнорируются
  регистр и пунктуация, `ё` приводится к `е`. Числа и написанные словами
  числительные различаются. Словарь приложения и резервная подмена Vosk отключены.
- **DER** — пропущенная речь, лишняя речь и перепутанные участники, в сумме
  делённые на длительность речи по разметке. Ниже — лучше. Итоговый тест
  учитывает одновременную речь и погрешность на границе не прощает
  (`collar=0`). Метки наподобие `speaker_1` сопоставляются с разметкой один
  раз на запись. В сравнении старый общий `UNKNOWN` считается одной меткой.
- **Voice ID по имени** — доля времени одиночной речи зарегистрированных
  участников, на которой старый метод присвоил именно правильный ID.
  `UNKNOWN`, пропуск и неправильное имя считаются отдельно. У самого
  Nemotron модели для диаризации этой метрики нет: номера действуют внутри одной записи.

Сводные WER и DER рассчитаны по суммам ошибок и объёма эталона на общем наборе
записей, которые успешно обработали все выбранные модели в группе. Сводка
показывает покрытие, чтобы неполный прогон не выдавался за сравнение на всех файлах.

## Как повторить контрольный прогон

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -m voice_id_mvp.benchmark.datasets open-stt data/bench/open-stt-100 --count 100
& $py -m voice_id_mvp.benchmark.runner data/bench/open-stt-100/audio data/bench/open-stt-new --models gigaam vosk nemotron-asr
& $py -m voice_id_mvp.benchmark.datasets icsi data/bench/icsi --meeting Bdb001 Bed004 --start 300 --duration 120
& $py -m voice_id_mvp.benchmark.runner data/bench/icsi/audio data/bench/icsi-new --models legacy nemotron-diar --enrollment data/bench/icsi/enrollment
```

Для распознавания текста используется часть [Open STT](https://github.com/snakers4/open_stt)
`asr_calls_2_val` с ручной разметкой русских звонков. Фиксированная выборка из
100 клипов получена сортировкой по SHA-256 от строки `voice-id-mvp-v1:<путь>`;
список сохраняется в `selection.json`. Для говорящих используются моно записи
встреч и разметка NXT из [ICSI Meeting Corpus](https://huggingface.co/datasets/ggfox00000/dia-ICSIMeetingCorpus-all).
Тестируются интервалы 300–420 с. Старый метод получает до трёх образцов
одиночной речи на человека из диапазона 0–300 с того же разговора, без пересечения
с тестом. Рабочая база голосов в тесте не используется. Nemo получает только
тестовое аудио. [SpeechBrain emotion diarization](https://huggingface.co/speechbrain/emotion-diarization-wavlm-large)
размечает эмоции и не участвует в сравнении людей.

Использованы официальные [Nemotron 3.5 ASR](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b)
и [Nemotron 3 Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization)
в формате Q8 (8-битные веса) через [NeMo-Speech.cpp v0.3.0](https://github.com/NVIDIA/NeMo-Speech.cpp/releases/tag/v0.3.0).
Текст распознаётся с русским языковым параметром `ru-RU`, диаризация запускается
с профилем `v3-offline`. Размеченные телефонные звонки и встречи полезны для
контрольного сравнения, но не измеряют качество на коротких репликах и шуме
конкретной пекарни. Возможное пересечение корпусов с данными обучения моделей не проверено.

## NVIDIA Nemotron в диалоге

Выберите «NVIDIA NeMo / Nemotron» в списке «Как разделить говорящих» на
[главной странице](http://127.0.0.1:18100/). Чтобы включить его по умолчанию,
поставьте `DIARIZATION_ENGINE=nemotron` в `.env` и перезапустите сервисы.
Для одной диаризации можно установить только нужные веса:

```powershell
.\.venv\Scripts\python.exe -m voice_id_mvp.benchmark.setup_nemo diarization
```

NeMo различает незнакомых людей по номерам. Существующий Voice ID всё ещё
проверяет имя на отдельных незашумлённых чужим голосом репликах; при
неуверенности поле `speaker_id` остаётся `UNKNOWN`. Моменты одновременной речи
помечаются: обычная расшифровка слышит смешанный звук и не умеет разделить слова
двух людей, даже когда диаризация заметила обоих.

Запрос к API без текста: `POST http://127.0.0.1:18103/diarize` с файлом
`audio`. Для текста по репликам используйте `POST /dialogue?diarization_engine=nemotron`.
Прежний метод остаётся настройкой по умолчанию.

В Docker после сборки основных сервисов установите Linux runtime и веса в общую
папку `models`:

```powershell
docker compose run --rm --no-deps transcription python -m voice_id_mvp.benchmark.setup_nemo diarization
```

Запуск Docker на Windows не нужен для отдельного приложения или нативного сервиса.
